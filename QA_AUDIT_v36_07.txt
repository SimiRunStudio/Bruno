DOCUMENTATION-DRIVEN FINDINGS FIXED
----------------------------------
1. GPT-Live uses session.input_transcript.delta and session.output_transcript.delta. The previous frontend listened to mismatched response/realtime event names, so captions could remain empty even while audio was active.
2. GPT-Live greeting is requested with session.commentary.append after session.started; response.create was not the documented GPT-Live greeting workflow.
3. Added trusted developer greeting input to session creation and a session-wide spoken greeting request after startup.
4. Added separate user and teacher transcript buffers with independent commit timers for full-duplex speech.
5. Added microphone mute/unmute control using the local WebRTC audio track.
6. Added data-channel close handling and safe cleanup after failed/disconnected peer connections.
7. Kept the WebRTC media track as the audio transport and added visible audio controls when autoplay is blocked.
8. Increased close confirmation timeout to 15 seconds and explicitly report unconfirmed final usage when the channel closes early.
9. Preserved server-side API key protection and all v36.06 static path, origin, rate-limit and request validation protections.
