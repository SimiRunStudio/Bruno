ASMARON LANGUAGE ACADEMY v36.08 — WORKABILITY / VOICE RELIABILITY PATCH
=======================================================================

BASE
----
Built from the supplied v36.07 project. Existing lessons, course data, adaptive practice, phrasebook, local progress, AI Studio, transcription, embedded branding/teacher images, server-side API key handling and deployment configuration are retained.

ROOT CAUSE CLASS: LIVE STARTUP RACE / FALSE HEALTH CONFIDENCE
------------------------------------------------------------
1. The previous startup path did not invalidate pending asynchronous work when a user cancelled while the microphone permission prompt, ICE gathering, or backend request was still pending. A late getUserMedia resolution could leave a microphone stream alive or let a cancelled attempt continue.
2. The previous health endpoint only verified the text model. It could report AI ready while GPT-Live or the delegated Responses model was unavailable, leaving the voice button to fail later without a clear diagnosis.
3. Microphone mute only disabled the local track; it did not also issue the documented GPT-Live input-audio mute/unmute control event.
4. Provider error details were not consistently surfaced by the frontend.

FIXES
-----
1. Added monotonically increasing liveAttemptId. Every cleanup invalidates pending async operations.
2. After getUserMedia resolves, stale/cancelled attempts immediately stop every acquired track and return.
3. Late track, data-channel and peer-connection events from stale attempts are ignored.
4. End is enabled during startup; cancellation closes resources and prevents a later permission response from reviving the session.
5. Bounded ICE gathering to 15 seconds and overall startup to 45 seconds; backend request timeout remains bounded.
6. Cleanup closes data channel and peer connection, stops microphone tracks, clears timers and removes the audio element.
7. Mute/unmute now both disables/enables the local track and sends session.input_audio.mute / session.input_audio.unmute.
8. Health endpoint independently checks text, GPT-Live and delegated Responses model access. It reports liveReady and liveReason rather than implying text readiness means voice readiness.
9. Home/Settings connection status distinguishes text-ready from live-voice-ready and reports missing API key/model access clearly.
10. Frontend now prefers upstream provider detail when available.
11. Added Windows and shell launch scripts; local startup runs checks/tests and reads server secrets from ignored .env.
